Cradle Video Automation

Web Extension - Architektura Pobierania Plików

Prezentacja techniczna mechanizmów skanowania, parsowania DOM oraz wielowarstwowej strategii pobierania zasobów z platformy Cradle.

1. Discovery (Odkrywanie plików)

Rozszerzenie działa jako Content Script (`cradle-scanner.js`), który stale monitoruje strukturę DOM w poszukiwaniu zasobów.

Mechanika skanowania:

  • Skanowanie tabel w poszukiwaniu tagów <a href="...">.
  • Kategoryzacja: Skrypt analizuje strukturę strony i nagłówki tabel, aby bezbłędnie podzielić pliki na dwie grupy:
    • Acceptance (Wzorzec)
    • Emission (Plik końcowy/wyjściowy)
  • Filtrowanie śmieci: Skrypt ignoruje rozszerzenia graficzne i dokumenty, skupiając się na formatach wideo (.mp4, .mov, .mxf, .zip).

2. Rozwiązywanie problemu API (nc-download)

Głównym wyzwaniem na platformie są linki typu API (Nextcloud download endpoint), które nie posiadają rozszerzenia pliku w adresie URL.

// Przykład problematycznego URL z Cradle:
https://cradle.example.com/nc-download/1a2b3c4d5e6f

Strategia "Type Hinting":

Ponieważ URL nie mówi, czy plik to wideo czy PDF, skrypt stosuje zaawansowaną heurystykę:

  • Ekstrakcja nazwy pliku z wewnętrznych spanów (<span class="filename">video_v1.mp4</span>) otaczających link.
  • Mapowanie wyabstrahowanego rozszerzenia z powrotem na obiekt pobierania.
  • Jeśli skrypt zidentyfikuje, że link nc-download wskazuje pod spodem na grafikę, link ten jest pomijany.

3. Trójwarstwowa Architektura Pobierania

Po wyodrębnieniu poprawnych adresów URL, system używa kaskadowej strategii pobierania plików na dysk użytkownika.

Priorytet 1 Delegacja do Desktop App (WebSocket)
Rozszerzenie wysyła JSON {action: "DOWNLOAD_FILES"} przez WebSocket do lokalnej aplikacji Pythonowej. To rozwiązanie jest najstabilniejsze dla ogromnych plików (MXF > 10GB).
Fallback 1 API chrome.downloads
Jeśli aplikacja desktopowa jest wyłączona, wiadomość DOWNLOAD_FILE trafia do background.js. Używane jest natywne API przeglądarki. Plus: pozwala zapisywać pliki w podfolderach. Minus: czasem blokowane przez CORS Cradle'a.
Fallback 2 Fetch API + RAM Blob
Metoda ostateczna (w downloadViaFetch). Plik jest pobierany przez fetch() w całości do pamięci RAM przeglądarki, po czym konwertowany na Blob i wymuszany do pobrania wirtualnym kliknięciem w tag <a>. Posiada limit wielkości pliku (~1.5GB).

4. Rola Service Workera (background.js)

W nowoczesnych rozszerzeniach Manifest V3, background.js pełni rolę efemerycznego Service Workera.

chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.action === 'DOWNLOAD_FILE') {
    // API chrome.downloads dostępne tylko w background.js
    chrome.downloads.download({
      url: message.url,
      filename: message.filename,
      conflictAction: 'uniquify'
    });
  }
  return true; // Asynchronous response
});

Background script służy tu za most delegujący akcje wymagające wyższych uprawnień przeglądarki, do których Content Script nie ma dostępu.

5. Architektura i Workflow

Proces przepływu danych od momentu załadowania strony do uruchomienia analizy końcowej.

1. Content Script (Skaner)
Monitoruje zmiany na stronie → Wyodrębnia linki → Rozpoznaje typy plików (Acceptance / Emission)
2. Router Pobierania
Rozszerzenie próbuje nawiązać połączenie WebSocket z lokalną aplikacją Desktopową.
Ścieżka A: Desktop App
Python przejmuje zadanie. Bezpiecznie pobiera wielkie pliki (>10GB) do wyznaczonego folderu roboczego.
Ścieżka B: Fallback (Przeglądarka)
Background SW używa chrome.downloads, lub ładuje plik do RAM (Blob) i wymusza pobranie z pominięciem CORS.
3. New Video Compare (NVC)
Zaraz po potwierdzeniu pobrania obu plików (Akcept i Emisja), system przekazuje ścieżki do lokalnego API NVC. Tam rozpoczyna się analiza klatka-po-klatce (frame difference), walidacja LUFS oraz analiza STT (Whisper).

6. Tworzenie Struktury (Prompt dla Claude)

Jeśli inny zespół chce odtworzyć ten system w swoim środowisku za pomocą LLM, ten prompt będzie idealnym punktem startowym do generacji bazy kodu:

Jesteś Senior inżynierem tworzącym rozszerzenia do Chrome (Manifest V3). 
Zaprojektuj strukturę plików i napisz kod dla rozszerzenia "Smart Downloader". 

Wymagania:
1. Rozszerzenie musi posiadać Content Script, który parsuje tabele na stronie i szuka linków <a href="...">.
2. Musi kategoryzować pliki na dwie grupy na podstawie klas i tekstu (np. pliki Wzorcowe i Emisyjne). Zwróć uwagę, że niektóre adresy URL to endpointy API (np. /nc-download), które wymagają odgadnięcia rozszerzenia pliku z innych elementów w DOM.
3. System preferencyjnie nawiązuje połączenie WebSocket z lokalnym serwerem na porcie 8765. Jeśli połączony, wysyła payload z linkami: {action: 'DOWNLOAD_FILES', files: [...]}.
4. Fallback: Jeśli WebSocket zawiedzie, Content Script używa chrome.runtime.sendMessage do przekazania adresów do Background Service Workera.
5. Background Worker odbiera wiadomość i uruchamia chrome.downloads.download() aby zapisać pliki w tle (z conflictAction: 'uniquify').
6. Utwórz komplet: manifest.json, content_script.js, background.js. Kod musi być nowoczesny (ES6+, async/await) oraz odporny na błędy sieciowe (graceful degradation).
Wygenerowano dla zespołów inżynieryjnych. Architektura: Content Script -> WebSocket / Background SW.
